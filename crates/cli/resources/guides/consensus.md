# Orchestrate Consensus

Consensus answers: **what implementation direction do the three finalized Discovery opinions genuinely agree on?** Read only the frozen request/context and the three selected public Discovery specifications. Do not re-investigate a repository or inspect private run state.

Resolve the exact eligible Discovery artifact for each slot before reconciling anything, using `orchestrate consensus inputs`. If a slot is missing or ambiguous, resolve it with the user first: never guess and never select the newest artifact. Write `proposal.json` only after the three exact artifacts are known, and finalize with those same three explicit `--opinion` selectors so the published parents are the artifacts you actually read.

Normalize equivalent conclusions, distinguish silence from contradiction, preserve material conditions, and retain meaningful dissent. For every mandatory consensus-derived requirement, declare `supporters` as the supporting slots and, where useful for explanation, `source_refs` keyed by slot. A requirement needs at least two supporting slots, and every requirement in the mandatory package must share the same strict-majority intersection. Do not synthesize rotating majorities.

Governing user constraints are not votes: faithfully include them or return no implementation-ready Agreement. Produce a useful comparison and a coherent package, or honestly return no consensus. Do not adopt, Build, or Audit. Stop after publishing the Consensus result.
